# 버전 관리

## 번호

- 제품 버전은 `VERSION` 한 줄입니다. 지금 **0.11**입니다.
- 다음부터 **0.01씩** 올립니다: `0.12` → `0.13` → … → `0.19` → `0.20`
- 0.1은 0.10과 같습니다. 표기는 `0.1`을 유지합니다.
- npm/PyPI용 `x.y.z`가 필요하면 `0.1` → `0.1.0`으로 맞춥니다.

## 한 버전에서 할 일

1. `VERSION`을 새 번호로 바꾼다.
2. `frontend/src/lib/version.ts`, `backend/app/__init__.py`, 패키지 `version` 필드를 맞춘다.
3. `CHANGELOG.md` 맨 위에 항목을 적는다.
4. 커밋 메시지에 버전을 넣는다. 예: `Release 0.12`
5. 태그: `git tag -a v0.12 -m "v0.12"`
6. `git push origin main --tags` (원격이 있을 때)

## 브랜치

- `main` — 동작하는 최신
- 기능 작업은 `feat/...` 또는 그냥 `main`에 직접 (개인 저장소)

## 커밋

- 한 커밋은 한 가지 이유
- 비밀(`.env`, App Key)은 커밋하지 않는다
- 실주문 연동을 넣는 버전은 CHANGELOG에 **키움 실호출**이라고 분명히 적는다
